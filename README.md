# IskraFOL — карта проектов

**IskraFOL** — общая организация для разработки игр, инструментов и связанных проектов. Этот репозиторий служит центральной картой экосистемы: здесь собраны основные проекты, их назначение и правила организации работы.

> Статусы и связи в карте отражают текущие договорённости и будут уточняться по мере развития проектов. Наличие проекта в списке не означает, что его репозиторий уже перенесён в организацию.

## Проекты

| Проект | Назначение | Репозиторий / статус |

| **FOL Engine** | Собственный игровой движок и базовые системы для будущих игр | [Anwite/FOL-Engine](https://github.com/Anwite/FOL-Engine) — активная разработка |
| **Old Legends** | Minecraft-мод о четырёх легендах: Herobrine, NULL, Entity 303 и Лик | [Anwite/four_old_legends](https://github.com/Anwite/four_old_legends) — отдельный репозиторий |

Подробные статусы, ближайшие цели, открытые PR и непроверенные сценарии собраны в **[реестре проектов](docs/PROJECTS.md)**. Правила статусов, подтверждения результатов и обновления карточек описаны в **[стандарте документации](docs/DOCUMENTATION-STANDARD.md)**. Правила согласования решений, межпроектных зависимостей, безопасности и возможного переноса репозиториев собраны в **[правилах управления экосистемой](docs/GOVERNANCE.md)**.

## Как устроена экосистема

```text
IskraFOL
└── iskrafol-hub                 Центральная карта
    ├── FOL Engine               Игровой движок
    ├── Old Legends              Minecraft-мод
    ├── Four-Old-Legends Website
    ├── «Обратной дороги нет»    Отдельный игровой проект
    └── FOL-AI                   Будущее направление
```

Это **логическая карта проектов**, а не утверждение, что все репозитории уже находятся внутри организации IskraFOL. Существующие репозитории пока остаются на своих текущих адресах. Переносить их будем отдельно и только после проверки.

## Назначение центрального репозитория

- Давать единую точку входа в проекты IskraFOL.
- Хранить краткие описания, ссылки и текущие статусы.
- Фиксировать согласованные решения об организации проектов.
- Описывать зависимости и общие планы, когда они определены.
- Помогать новым участникам понять структуру экосистемы.

## Принципы работы

1. **Один проект — один основной репозиторий.** Не объединяем несвязанные исходники в центральную карту.
2. **Сначала проверка, затем перенос.** Перед перемещением репозитория проверяем ссылки, доступы, настройки и сохранение истории Git.
3. **Не менять без необходимости.** Не переименовываем и не переносим существующие репозитории без отдельного решения.
4. **Приватность по назначению.** Видимость выбирается отдельно для каждого репозитория с учётом публикуемых материалов и стадии разработки.
5. **Решения фиксируются явно.** Предварительные идеи не считаются окончательными решениями, пока не согласованы.
6. **Документация следует за проектом.** Статусы и ссылки обновляются по мере реальных изменений.
