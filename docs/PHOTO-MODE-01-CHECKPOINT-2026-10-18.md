### Добавленные команды

`/legends photo spawn herobrine`, `null`, `entity_303`, `lik`, `oblivion`.  
`/legends photo face`, `/legends photo remove`, `/legends photo clear`, `/legends photo count`.

Доступны только с правами модератора, которые уже необходимы для `/legends`. Спавн — в четырёх блоках перед игроком, в свободном месте. Команды поиска и очистки работают только с постановочными сущностями `LegendNpcEntity.isPhotoMode()`, в радиусе 48 блоков, максимум 16 поблизости.

### Гарантии дизайна

- Сохранённый в данных NPC флаг `PhotoMode`. Восстанавливает `NoAI`, `NoGravity`, неуязвимость, постоянное сохранение. Постановочный NPC не выполняет обычное преследование, реакцию на взгляд и свой 30-секундный таймер. Предусмотрена защита от обычного деспавна в Peaceful.
- **Обычные легенды и сюжеты** `HerobrineBrain`, `LikBrain`, `FeudDirector`, `LegendaryMeetingEvent` не менялись, фотокоманды их не удаляют.
- Файлы: новый `PhotoModeCommands.java`, изменения `LegendNpcEntity.java` и `LegendCommands.java`, отдельная документация.
- Комментарии изменений написаны на русском.

### Проверка / статус

**Выполнено:** анализ текущего кода и статическая проверка структуры, вызовов и команды регистрации.  
**Не выполнено:** компиляция Java 25, игра, фотографии с новым NPC, проверка перезахода в мир и Peaceful. Требуется ручная проверка владельцем привычным Play/FOL_JVMTEST в IntelliJ.

Владелец не хочет установки VirtualBox и дополнительных внешних систем, минуты GitHub Actions на исходном аккаунте исчерпаны; на этом этапе **CI не запускать**.

**Слияния:** в `main` и ветку BUS-STOP-05 ничего не слито. PR #62 пока Draft. После ручной приёмки владельцем — продолжить осеннюю фотосессию.

## КТ — первая реальная компиляция PHOTO MODE и устранение API ошибок

Владелец сделал локальный запуск `FOL_JVMTEST` через IntelliJ IDEA на ветке `feature/photo-mode-staged-npcs-2026-10-18`. Gradle дошёл до `compileJava` и сообщил **3 ошибки** в `LegendNpcEntity.java`: отсутствует переопределяемый `Monster.shouldDespawnInPeaceful`, отсутствует его вызов `super.shouldDespawnInPeaceful()`, и нет `ValueInput.getBoolean(String)`.

**Исправление:** [commit c73d241f](https://github.com/Anwite/four_old_legends/commit/c73d241f0743b937d48364c9d295a711b7c76fee) — удалён метод `shouldDespawnInPeaceful`, флаг `PhotoMode` загружается через доступный в MC 26.3 `getBooleanOr("PhotoMode", false)`. Регистрация `oldlegends:legend_npc` и естественное поведение настоящих NPC не изменены. В 26.3 Peaceful-политика относится к `EntityType`; специфическое поведение фотоперсонажей на Peaceful требует ручной проверки.

**Повторная компиляция пока не подтверждена**: пользователь ещё не сделал Pull и перезапуск после этого коммита. `main` не затронут, PR #62 Draft, Actions/VirtualBox не запускались.
