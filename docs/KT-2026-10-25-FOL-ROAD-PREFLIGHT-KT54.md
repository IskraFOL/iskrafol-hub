# КТ 54 — Four Old Legends 1.3.0: ранняя NBT-проверка дорожного стенда

**Дата:** 25 октября 2026 г.  
**Протокол:** Release First; отдельная ветка → статическая проверка → пользовательский тест → только затем согласованное слияние.

## Основание
После игрового теста КТ51 `/legends road test` на одноразовом Creative Superflat выставил первый прямой сегмент, затем отказал при правом повороте с `EMPTY_NBT_FOOTPRINT`. Общий откат сработал. Наличие корректного исходного NBT не доказывает корректную сериализацию Runtime StructureTemplate; природа ошибки пока неизвестна.

## Найденный дефект
1. `RoadDirector.preflightFlatBench()` проверял семь этапов только по рельефу. Полная проверка NBT проходила при размещении очередного сегмента, **после начала записи мира**, поэтому пустой поворот обнаруживался слишком поздно.
2. `scripts/check_road_bench_preflight.py` проверял устаревший `benchAreaIsClear()`, отсутствующий в текущем `RoadDirector`. Тест сам стал несовместим с интеграционной веткой.

## Реализовано
- Отдельная ветка `fix/road-bench-nbt-preflight-2026-10-25` **на основе** объединённой тестовой ветки `test/fol-1-3-0-unified-kt45-2026-10-24`.
- На каждом из 7 этапов до начала каких-либо записей загружается NBT и вызывается существующая `RoadPlacementSafety.preflight()`. Причины отказа и этап сообщаются игроку.
- Статический Python-тест переписан на текущие `preflightFlatBench`, `snapshotFlatBench`, пред-проверку, snapshot и rollback.
- Откат при ошибке и строгие блокировки размещения сохранены. **NBT, геометрия, пользовательские сейвы, main не менялись**.

## Результаты и ограничения
**PASS:** повторная проверка кода в GitHub подтвердила наличие раннего preflight, правильную последовательность preflight → snapshot → place, сохранённый rollback, устранение ссылки на старый метод.  
**NOT RUN:** запуск скрипта Python в полном checkout; JDK25, Gradle, Minecraft 26.3, реальное размещение и возврат в мир.
