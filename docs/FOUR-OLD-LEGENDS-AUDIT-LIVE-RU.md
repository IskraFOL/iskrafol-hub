## 1. Что это за аудит и как читать статусы

Аудит — это проверка не только того, собирается ли мод, но и того, как он ведёт себя в настоящем Minecraft: создаёт ли дороги, удаляет ли временные сущности, сохраняет ли предметы, возвращает ли мир в прежнее состояние.

| Статус | Что означает простыми словами |
|---|---|
| **Проверено в Minecraft** | Игра действительно запускалась в изолированном мире; есть журнал и отчёт теста. |
| **Проверено сборкой** | Код компилируется на Java 25, но не все игровые действия испытаны. |
| **Слито в main** | Исправление стало частью основной ветки репозитория. Это не то же самое, что опубликованное обновление мода. |
| **Черновик / открытый риск** | Работа подготовлена либо проблема найдена, но полноценной безопасности ещё не доказано. |

GitHub Actions запускает настоящую тестовую копию Minecraft 26.3, обычно в Superflat/Creative-мире. Это **не пользовательский мир**. Мы отдельно проверяем обычную работу, перезаход в мир и аварийные ситуации: успешный тест одного варианта не доказывает остальные.

## 3. Дороги: исправлены разрывы и поведение выгруженных участков

**Какая была проблема.** Структуры дороги могли стыковаться с пробелами, а сеть иногда пыталась продолжаться от конца, находившегося в выгруженном чанке. Из-за этого рост останавливался либо обращался к участку мира, которого сейчас нет в памяти.

**Что сделали.** Исправили геометрию и привязки дорожных шаблонов; научили алгоритм выбирать доступные концы дороги и откладывать попытку, если соседние чанки ещё не загружены. Начальный посев дороги тоже не обращается к выгруженному рельефу. Изолировали состояние дорожной сети при переключении миров.

**Как доказали.** Статическая проверка подтвердила **24 из 24** дорожных соединений; в настоящем мире при низком напряжении сеть не создавалась, при нужном — появлялась и увеличивалась до **44**, а затем до **66** занятых клеток. При удалении игрока на большую дистанцию дорога сохраняла свой конец, после возвращения продолжала строиться. Тест не использовал команду принудительной генерации.

**Доказательства:** [стыки и Minecraft #23](https://github.com/Anwite/four_old_legends/pull/23) · [выгрузка / возврат, run 38936377349](https://github.com/Anwite/four_old_legends/actions/runs/38936377349) · [естественный рост, run 38939109191](https://github.com/Anwite/four_old_legends/actions/runs/38939109191).

**Что осталось.** Для старых миров ещё не доказана совместимость исторических координат `RoadEnd`; автоматически переписывать их нельзя. Нужно проверить переход *мир A → B → A*, последствия повреждённого сохранения и разработать собственный шаблон правого поворота: естественные правые повороты пока отключены.

## 4. «Забвение»: атмосфера без разрушения дома игрока

**Какая была проблема.** Изначально «Забвение» определяло подходящие для стирания блоки по их типу. Но тот же книжный шкаф или каменный кирпич мог поставить сам игрок. Значит, визуально «правильный» эффект теоретически мог повредить настоящую постройку.

**Что сделали.** Теперь по умолчанию сущность проявляется визуальными и звуковыми эффектами, **не уничтожая блоки**. Физическое удаление доступно только тогда, когда владелец мира сознательно включил обе настройки: `allowGriefing=true` **и** `oblivionEraseBlocks=true`. На русском и английском есть предупреждения о риске.

**Как доказали.** Настоящий игровой тест подтвердил три ситуации: при запрете изменений — блоки целы; при обычном безопасном режиме — блоки целы; при обеих явно разрешающих настройках — удаление действительно происходит. Отчёт: `PASS`, ошибок нет.

**Доказательства:** [PR #38](https://github.com/Anwite/four_old_legends/pull/38) · [Minecraft run 38940217902](https://github.com/Anwite/four_old_legends/actions/runs/38940217902).

**Ограничение.** Если человек намеренно включит физическое стирание, обычные блоки его построек по-прежнему могут быть затронуты. Полный учёт «кто поставил этот блок» пока не реализован.

## 5. Херобрайн и Лик: временные персонажи не должны оставаться навсегда

**Какая была проблема.** Временные преследователи могли продолжать существовать в мире после отключения их искусственного интеллекта. При повторных появлениях это грозило накоплением лишних сущностей.

**Что сделали.** Добавили явную очистку временных NPC при выключении соответствующей механики, выходе игрока и сбросе серверного состояния; в снах добавили проверку загрузки целевого участка перед обращением к рельефу.

**Как доказали.** В тестовом Minecraft два раза создали настоящие сущности и выключили оба ИИ. Фактическое число Херобрайнов и Ликов в мире прошло цикл **1/1 → 0/0 → 1/1 → 0/0**, без «остаточных» NPC.

**Доказательства:** [PR #39](https://github.com/Anwite/four_old_legends/pull/39) · [Minecraft run 38941549757](https://github.com/Anwite/four_old_legends/actions/runs/38941549757).

**Ограничение.** Полный сценарий сна и отдельная проверка нескольких миров ещё не закрыты соответствующим игровым тестом.

## 6. Сюжетные сцены: мир возвращается к прежнему состоянию

**Какая была проблема.** «Легендарная встреча» и «Летописец Лика» временно перестраивают большую область под сюжетную сцену. Нужно гарантировать, что запрет на изменение мира действительно действует, а после завершения исходные блоки возвращаются.

**Что сделали.** При `allowGriefing=false` запуск двух сцен запрещён, включая ручную команду. Если игрок выключает этот параметр посреди сцены, мод завершает её и откатывает временную постройку.

**Как доказали.** Испытание реального Minecraft сравнило **каждый** блок после отката с его прежним состоянием: «Легендарная встреча» — **4 291 блока, 0 различий**; «Летописец Лика» — **1 380 блоков, 0 различий**.

**Доказательства:** [PR #42](https://github.com/Anwite/four_old_legends/pull/42) · [полная проверка BlockState, run 38946871410](https://github.com/Anwite/four_old_legends/actions/runs/38946871410).

**Ограничение.** Это штатное восстановление. Если Minecraft аварийно завершится посреди построения, исходные состояния блоков пока находятся лишь в оперативной памяти. Мы подготовили отдельный [план надёжного журнала](https://github.com/IskraFOL/iskrafol-hub/blob/main/docs/SCENE-CRASH-RECOVERY-WRITE-AHEAD-PLAN-2026-10-16.md), но не внедрили его без проверки сохранения **до** изменения мира.

## 7. ItemHaunt: что проверено и почему пока не готово к релизу

**Что делает механика.** Мод ненадолго забирает предмет из обычного инвентаря и позже возвращает его в другое место. Это интересный мистический эффект, но предмет при этом настоящий. Если процесс завершится внезапно, он может пропасть либо задвоиться из-за несовпадения двух сохранений.

**Подготовленное исправление.** В [черновике PR #40](https://github.com/Anwite/four_old_legends/pull/40) предметы записываются в отдельную очередь SavedData; при повреждении очереди новые пропажи блокируются. PR прошёл две Java 25 сборки, но **не слит в main**.

**Испытание № 1.** Из инвентаря взяли **5 алмазов**, записали один отложенный стак, заново прочли очередь в той же работающей игре, вернули **ровно 5**, очистили запись. Повреждённые данные блокируют новые изъятия. [Minecraft run 38943887428](https://github.com/Anwite/four_old_legends/actions/runs/38943887428) — **PASS**.

**Испытание № 2.** В одноразовом мире сохранили ещё не возвращённый стак, нажали **Save and Quit**, затем заново открыли этот же мир **в том же процессе Minecraft**. Очередь восстановилась из физического файла; после возврата в инвентаре было ровно **5 алмазов**, повторное действие не создало дополнительных. [Minecraft run 38948269865](https://github.com/Anwite/four_old_legends/actions/runs/38948269865) — **PASS**. В этом испытании тестовая ветка специально отключила обычный автоматический возврат при выходе, чтобы проверить именно сохранение очереди; **в релизный код этот обход не входит**.

**Что ещё не проверено.** Полное выключение JVM и запуск Minecraft заново, внезапное убийство процесса во время записи, конкуренция сохранения инвентаря и очереди, полный инвентарь и предметы со сложными свойствами. Данные двух файлов не сохраняются одной атомарной операцией. Поэтому **два зелёных теста не означают гарантии сохранности при краше**.

**Решение на текущую КТ:** PR #40 остаётся черновиком вне `main`. **Важно:** существующий код `main` также небезопасен при внезапном выключении: настоящий стак уже извлекается из PlayerData и находится только в памяти, а `itemHauntEnabled=true` по умолчанию. Пока исправление не проверено и не выпущено, рекомендуется отключить `itemHauntEnabled`. Подготовлен отдельный [безопасный вариант PR #47](https://github.com/Anwite/four_old_legends/pull/47): предметы перемещаются только между обычными слотами *одного инвентаря игрока*, без извлечения из PlayerData и отдельного файла очереди. Цена безопасности — игрок может найти вещь сразу, вместо задержки 1–3 минуты. Его игровой тест ещё не подтверждён.

### Запись 004 — 16.10.2026, доказано исчезновение предмета при потере файла очереди

- **Результат:** [Minecraft run 38954584753](https://github.com/Anwite/four_old_legends/actions/runs/38954584753) завершился **PASS именно как демонстрация уязвимости**, а не как успех защиты. В одноразовом мире 5 настоящих алмазов переместились из инвентаря в ожидающую очередь; после штатного сохранения файла игрока тест *искусственно удалил* единственный `item_haunt_pending.dat`, затем снова загрузил мир. Результат: `TAKEN: pending=1, stored=1, diamonds=0`; `REOPENED: 0/0/0`; `RETURNED: 0/0/0`; `SECOND: 0/0/0`. Алмазы исчезли; механизм не смог восстановить отсутствующую очередь. Это **инъекция сбоя**, а не авария JVM в момент записи.
- **Найден риск в опубликованной логике:** в производственном `main` изъятые предметы вообще сохраняются только в оперативной памяти и до штатного `flush` потенциально пропадают при краше. Конфигурация `itemHauntEnabled` в коде включена по умолчанию. До исправления безопаснее её отключить.
- **Отдельная реализация:** [PR #47](https://github.com/Anwite/four_old_legends/pull/47) (**draft, не в main**) больше не вынимает реальные вещи из PlayerData. Вместо прежней пропажи на 1–3 минуты меняются местами / перемещаются два слота обычного инвентаря (9–35); хотбар, броня и вторая рука не трогаются. **Сборка Java 25 — PASS:** [run 38956113405](https://github.com/Anwite/four_old_legends/actions/runs/38956113405).
- **Новый игровой тест:** [диагностический PR #48](https://github.com/Anwite/four_old_legends/pull/48) — команды только для CI, создают 5 алмазов и 7 камней, проверяют перемещение между слотами, затем Save and Quit → повторный вход и перестановку при заполненной сумке. Итог игры **пока не подтверждён**; нельзя считать компиляцию полной проверкой сохранности.
- **Холодный JVM-тест:** [run 38954821495](https://github.com/Anwite/four_old_legends/actions/runs/38954821495) тоже завершился **FAIL из-за отсутствия обнаруженного GUI-окна второй сессии**, несмотря на отдельную вторую JVM и логи инициализации Minecraft 26.3. Восстановление очереди между двумя JVM **не доказано**. Число прогонов растёт из-за диагностики стенда.
- **Релизное решение:** `main` не изменён, публикаций нет; черновые тестовые команды не вливаются в production.
