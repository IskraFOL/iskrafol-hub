# Предпереносный аудит репозиториев IskraFOL

**Дата проверки:** 13 октября 2026 года  
**Цель:** оценить подготовленность всех текущих проектов к возможному переносу в организацию IskraFOL и зафиксировать риски.  
**Объём:** удалённые метаданные GitHub, ветки, PR, основные конфигурационные файлы и доступное содержимое репозиториев.

> Это аудит и план подготовки, а не выполнение переноса. В ходе проверки не менялись владельцы и видимость репозиториев, не сливались и не закрывались PR, не удалялись ветки.

## 1. Итог

В организации `IskraFOL` сейчас один публичный репозиторий — [iskrafol-hub](https://github.com/IskraFOL/iskrafol-hub). Три основных проектных репозитория находятся у `Anwite` и приватны.

|---|---|---|---|
| IskraFOL Hub | [IskraFOL/iskrafol-hub](https://github.com/IskraFOL/iskrafol-hub) | Public | Уже в организации; перенос не нужен |

| Old Legends — Minecraft Mod | [Anwite/four_old_legends](https://github.com/Anwite/four_old_legends) | Private | Сначала разобраться с открытым и закрытым, но не слитым PR; проверить публикационный процесс |
| Four Old Legends Website | [Anwite/four-old-legends-website](https://github.com/Anwite/four-old-legends-website) | Private | Сначала сохранить зависимость PR № 2 от PR № 1 и выполнить локальную сборку |

## 2. FOL Engine

- **Основная ветка:** `main`; репозиторий приватный.
- **Открытые PR:** поиск открытых PR не обнаружил.
- **История PR:** PR № 1–9 отмечены как слитые. В частности, PR № 7 добавил логгер с временными метками и записью в файл, PR № 8 интегрировал Time System, PR № 9 добавил загрузку текстур и поддержку UV материалов.
- **Проверка Logger по удалённому коду:** в `main` присутствуют временные метки с миллисекундами, запись в файл в режиме добавления, единый формат сообщений, консольный резервный вывод при ошибке открытия файла и явный `Shutdown()`. Точка входа обрабатывает исключения и завершает работу с кодом ошибки; инициализация движка выполняет откат при ошибке SDL/рендерера.
- **Ветки:** обнаружены `main` и ветки завершённых функций, включая `feature/logger-file-timestamps`, `feature/game-loop-time-integration` и `feature/texture-material-system`. Удалённый файл `Engine/Core/Logger.cpp` в `main` и `feature/logger-file-timestamps` имеет одинаковый blob SHA, но `CMakeLists.txt` отличается. Это не доказывает, что вся ветка идентична `main`; автоматически удалять ветки нельзя.
- **Документация:** корневой README пока содержит только заголовок `# FOL-Engine`; это не мешает переносу Git-истории, но оставляет слабую точку входа для будущих участников.
- **Зависимости:** CMake подключает SDL из `ThirdParty/SDL` и связывает движок с Windows-компонентами рендеринга. Нужно убедиться, что сторонний код, история и лицензии сохраняются при переносе.
- **CI и сборка:** проверка через интеграцию не вернула PR workflow runs для проверенных коммитов. Это не доказывает отсутствие всех GitHub Actions или иных CI. Сборка на машине пользователя в этом аудите не запускалась.
- **Перед переносом:** сверить локальный репозиторий и незакоммиченные изменения; убедиться, что рабочая версия Logger и другие последние изменения находятся на удалённой ветке; проверить, какие завершённые ветки действительно нужны; улучшить README; проверить Actions, доступы и внешние ссылки.

**Оценка:** первый кандидат на перенос после локальной сверки и проверки настроек. Не требуется сливать дополнительные PR только ради переноса.

## 3. Old Legends — Minecraft Mod

- **Основная ветка:** `main`; репозиторий приватный.
- **Текущая конфигурация:** в `gradle.properties` указаны Minecraft `26.3`, Fabric Loader `0.19.5`, Loom `1.17.18`, версия мода `1.2.0`, Fabric API `0.161.0+26.3`. В `build.gradle` настроен Java 25.
- **PR № 1:** [Audit fixes: config sync, recorder audio, and world cleanup](https://github.com/Anwite/four_old_legends/pull/1) открыт. В его описании заявлены успешная локальная сборка и клиентские проверки; многопользовательская синхронизация остаётся непроверенной. Эти результаты не воспроизводились в рамках данного аудита.
- **PR № 2:** [Align legend skins with website card designs](https://github.com/Anwite/four_old_legends/pull/2) закрыт, но не слит. Ветка `website-card-skin-alignment` всё ещё обнаруживается. Закрытие не означает, что изменения попали в `main`.
- **Содержимое PR № 1:** список изменений включает активные исходники `src/main` и `src/client`, ресурсы и удаление устаревшего вложенного дерева `src/src`. Перед любым будущим слиянием следует отдельно проверять дифф и итоговую структуру.
- **Документация и лицензия:** корневой `README.md` и файл `LICENSE` по ожидаемым путям не найдены. При этом `fabric.mod.json` объявляет лицензию MIT. До дальнейшей публикационной работы следует согласовать лицензионный файл и добавить полезный README; само по себе это не блокирует сохранение приватного репозитория при переносе.
- **Публикация:** мод уже имеет внешнюю публикационную историю по контексту проекта. Нужно проверить адреса проекта, токены/секреты публикации и настройки Modrinth/CurseForge отдельно, не публикуя секреты в документации.
- **CI и сборка:** интеграция не вернула PR workflow runs для проверенного коммита. Сборка и запуск в этом аудите не выполнялись.
- **Перед переносом:** сохранить PR № 1 и ветку закрытого PR № 2 без изменений; проверить локальную синхронизацию, публикационные процессы, доступы, релизы и ссылки; уточнить лицензионный файл и README.

**Оценка:** кандидат на перенос после проверки PR № 1 и публикационных настроек. Не сливать PR и не удалять ветки в рамках аудита.

## 4. Four Old Legends Website

- **Основная ветка:** `main`; репозиторий приватный.
- **Состояние основной ветки:** в ней пока не обнаружен `package.json` или `index.html`; основа приложения хранится в ветках открытых PR, а README в проверенной ветке содержит только заголовок.
- **PR № 1:** [Set up website project with React, TypeScript and Vite](https://github.com/Anwite/four-old-legends-website/pull/1) открыт и основан на `main`. В его ветке присутствуют `package.json`, `package-lock.json`, конфигурация Vite/TypeScript и исходники React.
- **PR № 2:** [Refine atmospheric homepage design](https://github.com/Anwite/four-old-legends-website/pull/2) открыт и основан на ветке PR № 1 (`feature/website-project-setup`). Не менять базу или порядок интеграции без отдельного решения.
- **Команды проекта:** в `package.json` есть `build` (`tsc -b && vite build`), `dev` и `preview`; отдельная команда тестов не объявлена.
- **Безопасность:** проверенный `.gitignore` исключает `.env`, `.env.*`, `node_modules` и `dist`, оставляя возможность для `.env.example`. Это полезно, но не заменяет проверку истории на секреты.
- **Визуальная и функциональная проверка:** локальная сборка, запуск, адаптивность и сверка с макетом не выполнялись в этом аудите.
- **CI:** интеграция не вернула PR workflow runs для проверенных коммитов; это не исчерпывающая проверка всех CI-настроек.
- **Перед переносом:** сохранить PR № 1 и PR № 2 вместе с их зависимостью; выполнить локально `npm ci`, `npm run build` и `npm run dev`; проверить изображения-заглушки, ссылки, домен/хостинг и настройки деплоя, если они существуют.

**Оценка:** перенос лучше отложить до локальной сборки и стабилизации PR. Сливать PR только ради переноса не нужно.

## 6. Проекты без репозитория

### «Обратной дороги нет»

Пока репозиторий не определён. До создания нужно выбрать владельца и видимость, согласовать структуру для сценария, персонажей, сцен, ресурсов и технической части. Сюжетные материалы остаются черновыми, пока не утверждены отдельно. После решения о месте хранения можно провести начальный аудит перед добавлением в организацию.

### FOL-AI

Репозиторий пока не создан / не определён. Сначала сформулировать назначение, границы проекта и критерии начала реализации. Не создавать пустой репозиторий только ради симметрии с другими проектами.

## 7. Ограничения аудита

Из удалённой интеграции нельзя надёжно установить состояние локальной рабочей копии пользователя. В этом аудите не запускались локальные сборки и тесты, не проверялись полностью:

- все секреты и вся история файлов;
- collaborators, команды и фактические права доступа;
- настройки защиты веток, Actions secrets, окружения и сторонние интеграции;
- все релизы, пакеты, домены, хостинг и публикационные токены;
- наличие локальных незакоммиченных изменений;
- визуальная корректность сайта и все игровые сценарии мода.

Отсутствие workflow runs в ответе доступной интеграции не является доказательством отсутствия CI. Любые выводы о готовности ограничены проверенными удалёнными метаданными и файлами.

## 8. Очерёдность подготовки

1. **FOL Engine:** сверить локальную рабочую копию с `main`, проверить незакоммиченные изменения и ветки; затем проверить настройки репозитория.
2. **Old Legends:** проверить локальную рабочую копию, открытый PR № 1, закрытый неслятый PR № 2 и публикационные интеграции.
3. **Website:** проверить локальную сборку и сохранить зависимость PR № 2 от PR № 1; затем проверить деплой и ссылки.
4. **Hub:** поддерживать документацию; перенос не нужен.
5. **«Обратной дороги нет» и FOL-AI:** сначала принять решение о структуре и месте хранения.

Это рекомендуемый порядок аудита, а не обязательный порядок будущих переносов.

## 9. Решение по результатам

**Предпереносная проверка выполнена по доступным удалённым данным для всех трёх существующих проектных репозиториев и Hub.** Для двух проектов без репозиториев зафиксированы необходимые подготовительные решения.

Ни один репозиторий не переносился; видимость, PR и ветки не изменялись. Перед фактическим переносом нужно завершить локальную сверку и целевые проверки доступа, CI, публикаций и внешних интеграций.
