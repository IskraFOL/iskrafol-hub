## 3. Новый этап аудита кода — конкретные риски (без правок мода)

### P0 — автоматический мост не использует полную защиту ручной команды

**Код проверен**:
- `RoadDirector.growBridge` непосредственно вызывает `Structures.place(... bridge_segment ...)` после грубой оценки берега из `RoadBuilder.bridgeMakesSense`.
- `RoadTerrain.analyze(...bridge_segment...)` немедленно возвращает разрешение с **пустым Plan**.
- `Structures.place` применяет `RoadMountain.safeToPlace` лишь для горных NBT, а мост не помечен `isMountain`.
- `RoadMountain.safeBridge` вызывается в **ручном** `testMountain`, но в пути **естественного роста** моста отсутствует.

**Риск:** автоматическая вставка моста может не проверять защищённые блоки по полной площади NBT до изменения мира. Это **подтверждённый пробел защитного маршрута в исходниках**, но разрушение конкретной постройки игровым тестом не доказано.

**Блокирующее требование:** объединить полную проверку безопасности моста для авто/ручного пути, проверять весь реально заменяемый объём, руды, деревья, чужие постройки, воду под пролётом, соседние границы чанков; доказать отказ без изменения мира.

### P0 — неполный откат обычной дороги/моста при частичной вставке NBT

**Код проверен:** `Structures.place` сохраняет полный снимок для **горного NBT**, но для обычной дороги, угла и моста — только выемку `RoadTerrain.cut`. При `placeInWorld=false` или исключении вставки происходит откат выемки и горного снимка; **полного снимка самого обычного NBT-полотна нет**. При сбое на последующей стадии `replaceRoadStructureBlocks`/`RoadTerrain.finish` внешний `catch` только возвращает false — не восстанавливает прошлое состояние.

**Риск:** возможны частично оставленные блоки после ошибочного размещения или недостоверный RoadNetwork. Проверить с искусственным сбоем в одноразовом мире; нельзя объявлять повреждение уже воспроизведённым.

**Блокирующее требование:** атомарная схема подготовка → полный снимок реально меняемых блоков → вставка → постобработка → успех/полный откат; инъекция отказа до/после `placeInWorld`, проверка полного совпадения BlockState до/после.

### P1 — поворот одобряется по узкой проверке, а затем конец сети закрывается

**Код проверен:** `RoadBuilder.tryGrow` проверяет два коридора и жидкость в **одной точке** при выборе `CORNER_LEFT/RIGHT`, без проверки `RoadTerrain.analyze` по всему дорожному полотну угла. Затем `growCornerLeft`/Right может получить отказ `Structures.place`, после чего `growFromRandomEnd` **удаляет RoadEnd навсегда** (`if (!ok) net.removeOpenEnd(from)`). При этом прямой или иной безопасный вариант роста могли бы оказаться допустимыми.

**Риск:** сеть прекращает рост раньше необходимого при дереве, рудах, высотах. Требуется fail-closed без порчи мира, но и без уничтожения жизнеспособного конца после отказа одного варианта. Это кодовый риск, частота не измерена.

### P1 — не доказана безопасность декоративного объёма по бокам плоских NBT

`RoadTerrain.analyze` пропускает все локальные клетки **вне полотна** `onPavement`; реальные NBT содержат борта, фонари и декоративные блоки за пределами полосы, которые может заменить `StructureTemplate`. Нужно проверить **реальный footprint всех непрозрачных блоков**, а не лишь настил. Ориентир: не допустить замену блок-сущностей, руды, древесины, пользовательских конструкций, воды.

### P1 — игровые испытания ROAD 2.0, компиляция Java 25

- В PR #65/#68/#69 **нет подтверждённой свежей сборки новой цепочки с JDK 25 и полной приёмки Minecraft 26.3**.
- Ручная лестница теперь фиксирует вход у игрока (см. последний коммит), но визуальный PASS на этой версии всё ещё требуется.
- Автогенерация вверх/вниз/серпантин/лестница, четыре направления, снег/вода/руды/постройки, связь с мостом, Save & Quit/новый процесс — не закрыты.
- Правый автоматический поворот **намеренно отключён** (`ALLOW_RIGHT_TURNS=false`) до отдельного асимметричного NBT. Перед релизом нужно явно решить: делать ассет или документировать ограничение; не писать, будто оба направления поворотов включены.

### P2 — вспомогательные стены

Обе NBT-стены — **отдельные вспомогательные конструкции**, не часть дорожного настила и **пока не интегрированы в автоматический рост**. Успешный ручной спавн не равен работоспособному подпорному основанию; решение об интеграции/исключении из 1.3.0 принимать по готовности, не расширять скоуп бесконечно.

### P0: точная трасса кода перепроверена

1. **Автоматический мост:** `RoadDirector.growBridge()` действительно вызывает `Structures.place(... BRIDGE_STRUCTURE ...)` без `RoadMountain.safeBridge`. Путь ручной проверки через `RoadDirector.testMountain` вызывает `safeBridge`, но автоматический — нет. `RoadTerrain.analyze(bridge_segment)` возвращает пустой разрешённый план, `Structures.place` при этом проверяет `RoadMountain.safeToPlace` лишь для горных NBT. **Пробел защиты подтверждён повторным чтением кода**, игрового разрушения не воспроизводили.
2. **Откат обычных NBT:** в `Structures.place()` `mountainBefore` создаётся только для `RoadMountain.isMountain(name)`; для road_segment, road_corner, bridge_segment используется пустой снимок. `RoadTerrain.rollback(cut)` откатывает **только выемку до вставки**, но не реально заменённые `StructureTemplate.placeInWorld` блоки. Внешний `catch(Throwable)` возвращает false **без отката изменений из постобработки**. Риск неполного восстановления после исключения подтверждён кодом, не игровым сбоем.
3. **Связанный P1:** `RoadDirector.growFromRandomEnd()` удаляет `RoadEnd` после `GrowthResult.fail()` или неудачной вставки выбранного варианта; логика выбора угла предварительно не вызывает `RoadTerrain.analyze` по всему объёму.

### Требования к узкому будущему исправлению P0

- Единая проверка безопасности моста должна применяться **до всех изменений мира**, независимо от ручного/автоматического вызова; сохранение воды под пролётом и проходимости берегов обязательно.
- Предварительная проверка должна учитывать **занятые блоки NBT (а не один только дорожный настил)**, однако не запрещать пригодное место из-за окружающих декоративно пустых колонок. Защищённые постройки/руда/сундуки/дерево/BlockEntity — отказ без изменения мира.
- Для плоской дороги, угла, моста обеспечить полную транзакцию: предварительный анализ → снимок всех затрагиваемых состояний (и учёт BlockEntity, либо их защита от перезаписи) → выемка → вставка → постобработка → атомарный результат/откат.
- Исключение/false при `placeInWorld` и исключение при `replaceRoadStructureBlocks`/`RoadTerrain.finish` должны восстанавливать мир, а не просто возвращать false. Проверить обработку всего изменяемого объёма, а не только план `RoadTerrain.cut`.
- После кодового исправления — локальный регрессионный анализ, затем реальный Minecraft 26.3 + JDK 25 через IDE Play на **копии/одноразовом мире**. GitHub Actions не запускать (квота исчерпана), `main` не менять без согласованной игровой приёмки.

**Вывод этой итерации:** исходная КТ 1.9 актуальна; P0 подтверждены повторной трассировкой кода. Начало новой ревизии с нуля **не требуется**. Ни один новый B1–B8/Crash recovery/Dictaphone PASS не заявлен. В текущей итерации **изменён только этот документ аудита**, игровые исходники и Minecraft-миры не изменены.
