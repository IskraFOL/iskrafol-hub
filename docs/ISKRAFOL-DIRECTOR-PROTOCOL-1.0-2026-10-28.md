# IskraFOL — Протокол директора 1.0

**Статус:** утверждён владельцем 28 октября 2026 года.  
**Класс:** организационный внутренний регламент с долей фирменного юмора.  
**Совместимость:** дополняет [GOVERNANCE.md](GOVERNANCE.md) и правило **Release First**; не отменяет требования явного одобрения слияний, публикаций, удалений и других необратимых действий.

## Преамбула

> Руководитель вправе пить чай, придумывать Северный и задавать неудобные вопросы.
> Агенты обязаны превращать идеи в проверяемые результаты, а не в бесконечные новые релизные обязательства.

## Шесть статей

1. **Право на чай.** Руководитель определяет замысел, атмосферу, художественные ограничения и критерии качества, не обязан лично выполнять Gradle и писать Java.
2. **Идеи приветствуются, расширение релиза — нет.** Новые идеи отправляются в backlog. Для Four Old Legends действует **Release First**: сначала закончить согласованный релиз 1.3.0.
3. **Право финальной приёмки.** Ни зелёные тесты, ни закрытый PR сами по себе не означают выпуска. Критичные результаты показываются в настоящем игровом клиенте и принимаются владельцем.
4. **Без принудительной консоли.** По умолчанию предоставлять понятный интерфейс, готовый файл или удалённую проверку. Использование терминала на компьютере руководителя — только при его согласии, когда другие пути исчерпаны.
5. **Токеновая экономика.** Большие счётчики использования — повод проверять полезность и избегать повторных прогонов, но не основание придумывать денежные расходы. При достижении миллиарда разрешается торжественно открыть «Министерство токенов IskraFOL». Его бюджет, разумеется, контролирует чайник.
6. **Последнее слово — за владельцем.** Агент вправе рекомендовать, проводить согласованные проверки и готовить Draft PR, но не подменяет решение владельца об изменении состава релиза, слиянии, удалении ценных данных или публичном выпуске.

## Правило отчётности

- Каждый проект имеет собственную актуальную контрольную точку.
- Отдельно обозначать **PASS / FAIL / NOT TESTED**. Браузерный/статический тест не заменяет настоящий клиентский.
- Не дублировать ранее прошедшие дорогостоящие тесты без причины.
- Не дописывать нерелизные механики ради красивой статистики.
- Исходные миры, сюжетные книги, игровой корпус и ресурсы сохранять; изменения обратимы и идут через отдельные ветки.
- Не смешивать Minecraft и Wolfenstein в одном задании Codex.

## Торжественное приложение — Министерство токенов

**Председатель:** чайник.  
**Основная обязанность:** следить, чтобы ресурс превращался в работающий релиз, а не только в число на табло.  
**Единственный законный чрезвычайный повод:** `road_corner.nbt` снова решил жить собственной жизнью.
