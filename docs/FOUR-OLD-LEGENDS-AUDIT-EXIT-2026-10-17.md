## 2. Главное открытое ограничение, не скрывать

**P0 — аварийное восстановление временных построек сюжетных сцен.**
- После убийства JVM прежние BlockState обеих сцен пока не гарантированно восстанавливаются: main хранит снимок для отката в оперативной памяти. Вернувшиеся игроком блоки при обычной работе теперь защищены, но этого недостаточно после краша.
- **[Draft PR #52](https://github.com/Anwite/four_old_legends/pull/52)** содержит изолированный WAL и снимки BlockState; [run 39009114788](https://github.com/Anwite/four_old_legends/actions/runs/39009114788) подтверждает запись/чтение двух JVM и восемь fail-closed сценариев. Это **не тест аварийного восстановления игрового мира**.
- **[Draft PR #53](https://github.com/Anwite/four_old_legends/pull/53)** — CI-проверка Minecraft NBT, зависимая от #52. В доступных GitHub данных 17 октября завершённого runtime evidence для этого PR нет — не называть PASS.
- Обязательный технический финал: **журнал полностью подготовлен до первого `setBlock`**, сохранены исходное/ожидаемое состояния всех координат; неизвестные NBT и block entities не изменяются; kill JVM в середине построения; холодный запуск того же одноразового мира; восстановление без перезаписи изменений игрока; повторный запуск с незавершённым/повреждённым журналом не портит мир. Отдельно проверить поддержку `forceDirectory` на Windows.
- Пока этот сценарий не закрыт или не введена отдельно проверенная безопасная политика отказа от опасного строительства, **не объявлять 1.3.0 crash-safe**. Не сливать #52/#53 на основании одного зелёного Gradle.
