# Four Old Legends 2.0.0 — направление крупного обновления

**Дата решения:** 16 октября 2026 года  
**Статус:** направление и целевая версия согласованы; конкретные механики, объём и дата релиза пока не утверждены.

## Утверждённые решения

1. Следующее крупное обновление Four Old Legends планируется под номером **2.0.0**, переходя с текущей линии **1.2.0**. Номер версии — **цель разработки**, а не признак готового релиза; менять метаданные версии и публиковать сборку пока не требуется.
2. Это **контентное обновление**, а не только набор исправлений и аудит. Расширяется содержание **каждой из четырёх легенд**: Herobrine, NULL, Entity 303 и Лик. Ни одна из них не должна перетягивать весь апдейт на себя.
3. Сохранить главную атмосферу мода: редкое присутствие, тревожная неизвестность, постепенное раскрытие и минимум случайных скримеров.
4. Техническую часть тоже довести до надёжного состояния: завершить аудит, дорожный стенд и проверить устойчивость игровых сценариев в CI и на реальном клиенте.

## Предварительные идеи, ещё не утверждённый контент

- **Herobrine:** наблюдение издалека, следы присутствия, загадочные постройки.
- **NULL:** сбои привычной реальности, изменения окружения, необычные световые явления.
- **Entity 303:** формы преследования, необъяснимые вмешательства и следы активности.
- **Лик:** сны, остановки, дворы, жилые здания, предметы с неизвестной историей.
- Для всех четырёх: звуки, исследования и баланс частоты событий, чтобы избежать повторяемости.

Ранее предлагался ориентир **по два события на легенду**, четыре структуры/вариации, четыре–восемь звуков и четыре находки/взаимодействия. **Это лишь идея для планирования, не утверждённая спецификация.** Перечень надо сверить с уже существующими механиками мода и после этого сформировать отдельные ТЗ.

## Технический маршрут

1. Продолжить отдельный runtime-тест дорожного стенда: [PR #10](https://github.com/Anwite/four_old_legends/pull/10) и [журнал тестов](OLD-LEGENDS-ROAD-CI-2026-10-16.md).
2. Получить воспроизводимые доказательства отсутствия разрывов на всех стыках и только тогда рассматривать слияние исправлений дороги ([PR #9](https://github.com/Anwite/four_old_legends/pull/9)).
3. Завершить технический аудит и регрессию основных систем.
4. Инвентаризировать действующий контент, затем отдельными ветками и PR добавлять новые механики для **всех четырёх** легенд. По рабочему протоколу: изменения → сборка и CI → локальное подтверждение → слияние после согласования.
5. После полного тестирования отдельно принимать решение о публикации **2.0.0**.

**Запреты:** не считать перечисленные идеи реализованными; не менять официальную версию до готовности сборки; не сливать существующие PR без решения владельца.
