## Roads 2.0 — сохраняем понравившуюся многослойную подсыпку

Пользователь подтвердил, что **насыщенная вертикальная подсыпка/опорные блоки** под дорожным покрытием устраивают его значительно больше прежнего однослойного варианта. Это требование к дизайну **оставить неизменным**.

По повторным игровым стендам остаются блокирующие ошибки: `PROTECTED_BLOCK` на существующих дорогах / руде и `SLOPE_TOO_HIGH` / `SLOPE_TOO_LOW` на горных склонах. В текущем `RoadDirector.testBench` трасса из 7 деталей держится на **одной высоте Y**; тестовый стенд по назначению не является проверкой динамического приспособления к горному рельефу. Фикс должен разделить тестирование геометрии стыков и проверку естественного роста, не ослабляя защиту построек/руд/блок-сущностей.

Текущий Draft PR автоматической генерации: https://github.com/Anwite/four_old_legends/pull/68. Мод и клиент Minecraft 26.3 с JDK25 в этой ветке ещё не получили подтверждённую игровую проверку; `main` мода не менять до сборки и приёмки. Целевой релиз `1.3.0`.

## Решение Release First

Не расширять объём. Сначала безопасные дороги и тесты с реальным PASS, потом новые функции. Фотосессия — **публичная публикация подтверждена GitHub Pages**.

### Разбор новых игровых снимков стенда Roads 2.0, 20.10.2026
- **PASS, частичный:** первые прямые и повороты иногда успешно ставятся; многослойная подсыпка корректно видна в снегу/на склоне и визуально одобрена владельцем.
- **FAIL на природном склоне:** `SLOPE_TOO_HIGH` / `SLOPE_TOO_LOW`. Команда `/legends road test` из PR #65 генерирует 7 заранее фиксированных элементов на **одном Y**, с явным `flatten`; поднимающийся/падающий снежный склон закономерно выходит за MAX_CUT=3 / MAX_FILL=4. Это ограничение плоского теста, не подтверждение неисправности нового автоматического выбора склонов из Draft PR #68.
- **FAIL на деревьях:** `PROTECTED_BLOCK minecraft:spruce_leaves`. Не сносить растущие деревья автоматически ради теста — правильная консервативная защита, выбирать свободную полосу.
- **FAIL при повторной укладке на дорожное покрытие:** `PROTECTED_BLOCK minecraft:cobbled_deepslate` и ранее `minecraft:deepslate_bricks`; это может быть наложение существующих сооружений после многократных запусков / геометрия стыка. Обычные обработанные дороги нельзя разрешать разрушать без точного расчёта. Требуется повторная проверка в новом чистом месте после фикса corner-marker в PR #65.
- **Видимый стык/зазор** между двумя конструкциями на последнем снимке: требуется проверить координаты и footprint по двум соседним NBT, фотография сама по себе не доказывает точную величину расхождения.
- Следующий тест: чистая широкая ровная площадка для `/legends road test`; отдельный склон без деревьев/руды для `/legends road mountain up` или `down` только после сборки ветки #68 на Java 25. `allowGriefing=true` лишь во время испытания, затем вернуть false.

**Запрещено:** ломать safety на деревьях, руде и чужих постройках; терять многослойный фундамент; утверждать готовность Road 2.0 без подтверждённого Minecraft GameTest; сливать дорожные PR без разрешения.


### Дополнительная КТ: точечное исправление теста 20.10.2026
- В [Roads 2.0 Draft PR #68](https://github.com/Anwite/four_old_legends/pull/68) добавлена read-only проверка будущей цепочки `preflightFlatBench` перед первым изменением мира. Проверяются шесть полотен, принудительный мост остаётся особым случаем. Цель — исключить установку половины стенда при предсказуемом `SLOPE_TOO_*` или `PROTECTED_BLOCK`.
- По формульной модели `RoadGeom`: для SOUTH, WEST, NORTH, EAST все шесть стыков плоского стенда имеют по **6 соседних клеток полотна, 0 пересечений и 0 пропущенных клеток**. Данные рассчитаны по описанному `onPavement` footprint, не по фактическим блокам NBT. Видимый зазор между построенными кусками требует отдельной проверки фактических NBT/высот.
- После этой правки сборка Java 25 и клиент Minecraft 26.3 ещё не запускались. Это **не PASS тестового стенда**.

### Продолжение Road 2.0 — лестница подключена к генератору, подсказки сегментов

**По разрешению владельца** лестничная NBT `road_stair_connector_rise3.nbt` включена в `RoadBuilder` и `RoadDirector` в отдельной ветке [Draft PR #69](https://github.com/Anwite/four_old_legends/pull/69), поверх Draft PR #68. Генератор теперь имеет `STAIR_UP` и `STAIR_DOWN` с перепадом ±3, проверкой всей площадки и защитой чужих блоков, а `RoadEnd` после сегмента передаёт следующему куску корректную высоту и направление. Для спуска та же NBT устанавливается повёрнутой на 180°, без второй копии. Сохраняется многослойное каменное основание, как утверждено владельцем.

**Дополнительное требование:** у команды `/legends road mountain` теперь Tab-подсказки всех имеющихся видов: `straight`, `corner_left`, `corner_right`, `bridge`, `up`, `down`, `stair_up`, `stair_down`, `left_up`, `left_down`, `right_up`, `right_down`, `wall_left`, `wall_right`. Это 14 вариантов на 12 уникальных NBT; общий список `RoadDirector.TEST_VARIANTS` является источником подсказок и допустимых вариантов. Команды тестируют безопасно, не меняют дорожную SavedData и не разрешают перезапись блок-сущностей/деревьев/руды; принудительное размещение моста дополнительно защищено.

**Контрольные проверки:** локальный парсер подтвердил gzip-NBT 256 блоков, фактическое 6-блочное полотно и многослойное основание; расчёт 8 связок (4 направления света × подъём/спуск) с прямым сегментом прошёл, без расчётных швов, на выходе Y±3. Проверка через GitHub API подтвердила, что все 14 командных вариантов соответствуют существующим NBT. **Java25 компиляции и реальной Minecraft26.3 приёмки НЕТ.** В среде доступна только Java21, квоту Actions не расходовали, `main` Minecraft-мода и публичный сайт не изменяли.

**Оставшиеся ограничения:** автоматический выбор лестницы работает от открытого конца дорожной сети на подходящем уклоне, но ещё не строит путь непосредственно между *любыми двумя отдельно сформированными* дорогами. Подпорные стены только вручную тестируются, автоподстановка не реализована. PR #69 остаётся Draft до сборки и игровой проверки на копии мира и отдельного согласования.
