## 2. Активные проекты

### FOL Engine
- **Статус:** Active
- **Репозиторий:** https://github.com/Anwite/FOL-Engine
- **Видимость:** приватный
- **Назначение:** собственный игровой движок FOL Engine.
- **Подтверждено по удалённому GitHub:** ветка `main` содержит CMake-конфигурацию, систему времени и обновлённый Logger с временными метками, записью в файл и консольным резервным выводом. PR № 1–9 отмечены как слитые.
- **Контрольная точка — 14 октября 2026 года:** локальная копия находится в `C:\Users\vanyo\Desktop\ISKRAFOL_PROJECTS\FOL\FOL-Engine`. Ветка `main`, HEAD и `origin/main` совпадали на коммите `c0df411` (`Merge pull request #9 from Anwite/feature/texture-material-system`); `git status -sb` показывал чистое рабочее дерево, `git diff` и `git diff --cached` не показывали изменений.
- **Сборка и запуск подтверждены пользователем:** CMake 4.3.1-msvc1 успешно настроил и сгенерировал проект в Visual Studio 2026; обнаружен MSVC 19.50.35729.0 и Windows SDK 10.0.26100.0. После перенастройки CMake-кэша через интерфейс Visual Studio исполняемый файл `FOL_Engine.exe` запущен зелёным треугольником. Окно движка открылось, на экране отображаются 3D-кубы с текстурами; в консоли видны сообщения об успешной инициализации SDL3, создании окна, инициализации Direct3D 11, загрузке OBJ-модели и текстуры, запуске Engine и обновлениях кадров.
- **Проблема окружения, устранённая в этой сессии:** CMake cache содержал прежний абсолютный путь `C:\FOL\FOL-Engine`, тогда как рабочая копия находится в `C:\Users\vanyo\Desktop\ISKRAFOL_PROJECTS\FOL\FOL-Engine`. Повторная конфигурация через Visual Studio восстановила рабочий запуск. Для предварительной проверки также был успешно сгенерирован каталог `build-check`; он не является обязательным способом дальнейшей сборки.
- **Рабочее правило:** дальнейшую сборку и запуск выполнять привычным способом через Visual Studio — выбрать цель `FOL_Engine.exe` и нажать зелёный треугольник. Не направлять пользователя по дополнительным консольным командам и настройкам без реальной необходимости; перед изменением конфигурации сначала сверять уже установленный рабочий процесс. Не удалять проектные исходники и не менять рабочие настройки ради экспериментов.
- **Ближайшая цель:** сохранить это рабочее состояние и продолжить разработку с текущей сцены/рендера; перед следующей задачей свериться с актуальным кодом и предыдущим планом FOL Engine.
- **Не проверено в этой контрольной точке:** отдельный код завершения процесса после ручного закрытия окна, полный регрессионный прогон всех подсистем и CI/Actions в полном объёме.
- **Последнее обновление карточки:** 14 октября 2026 года.

## 4. Правила ведения реестра

- Использовать статусы и обязательные поля, описанные в [стандарте документации](DOCUMENTATION-STANDARD.md).
- Не считать задачу завершённой только потому, что она описана в PR или планах.
- Различать подтверждённые проверки, заявления из описаний PR, планы и непроверенные сценарии.
- Не считать локальные изменения частью удалённого репозитория без проверки.
- Не изменять и не сливать проектные ветки без необходимого согласования.
- Обновлять дату карточки после значимых изменений или проверок.
- Перед переносом сверять локальное состояние, ветки, доступы, CI и внешние интеграции по [предпереносному аудиту](REPOSITORY-AUDIT.md).
