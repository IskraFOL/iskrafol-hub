# Реестр проектов IskraFOL

**Последнее обновление:** 13 октября 2026 года  
**Назначение:** единая точка входа для отслеживания проектов экосистемы IskraFOL, их состояния, ближайших целей и незавершённых задач.  
**Стандарт карточек и статусов:** [Стандарт документации IskraFOL](DOCUMENTATION-STANDARD.md).  
**Предпереносная проверка:** [Аудит репозиториев IskraFOL](REPOSITORY-AUDIT.md).

## 1. Центральный хаб

### IskraFOL Hub
- **Статус:** Active
- **Репозиторий:** https://github.com/IskraFOL/iskrafol-hub
- **Видимость:** публичный
- **Роль:** центральная карта проектов и документация экосистемы.
- **Подтверждено:** реестр проектов, стандарт документации, правила управления и расширенный предпереносный аудит добавлены и повторно прочитаны из GitHub.
- **Ближайшая цель:** поддерживать карточки и ссылки в актуальном состоянии; перенос не требуется, поскольку Hub уже находится в организации.
- **Ограничения:** аудит удалённых файлов не подтверждает состояние локальных рабочих копий, секретов, collaborators или всех внешних интеграций.
- **Последнее обновление карточки:** 13 октября 2026 года.

## 2. Активные проекты

### FOL Engine
- **Статус:** Active
- **Репозиторий:** https://github.com/Anwite/FOL-Engine
- **Видимость:** приватный
- **Назначение:** собственный игровой движок FOL Engine.
- **Подтверждено по удалённому GitHub:** `main` содержит CMake-конфигурацию, систему времени и обновлённый Logger с временными метками, записью в файл и консольным резервным выводом. PR № 1–9 отмечены как слитые; открытых PR не обнаружено.
- **Ближайшая цель:** сверить локальную рабочую копию с удалённым `main`, проверить незакоммиченные изменения и актуальность рабочих веток; затем проверить сборку и настройки перед возможным переносом.
- **Не проверено:** сборка в рамках текущего аудита, состояние локальных файлов, Actions/CI в полном объёме и внешние интеграции.
- **Последнее обновление карточки:** 13 октября 2026 года.

### Four Old Legends — Minecraft Mod
- **Статус:** Verification
- **Репозиторий:** https://github.com/Anwite/four_old_legends
- **Видимость:** приватный
- **Назначение:** Minecraft-мод о четырёх легендах — Herobrine, NULL, Entity 303 и Лик.
- **Подтверждено по GitHub:** открыт PR № 1 с исправлениями конфигурации, синхронизации настроек, диктофона и очистки временных состояний. PR № 2 закрыт, но не слит; его ветка всё ещё обнаруживается.
- **Ближайшая цель:** сверить локальную рабочую копию, проверить открытый PR № 1 и отдельно решить судьбу закрытого PR № 2; проверить публикационные настройки перед возможным переносом.
- **Заявлено в описании PR № 1, но не перепроверено здесь:** сборка и отдельные клиентские сценарии прошли проверку.
- **Не проверено:** многопользовательская синхронизация, локальная сборка в рамках аудита, публикационные секреты и полный набор интеграций.
- **Ограничение:** не сливать PR и не удалять ветки без отдельного решения.
- **Последнее обновление карточки:** 13 октября 2026 года.

### Four Old Legends — Website
- **Статус:** Verification
- **Репозиторий:** https://github.com/Anwite/four-old-legends-website
- **Видимость:** приватный
- **Назначение:** официальный сайт проекта Four Old Legends.
- **Подтверждено по GitHub:** открыты два связанных PR: базовая настройка React, TypeScript и Vite, а также улучшение атмосферного дизайна главной страницы. PR № 2 основан на ветке PR № 1.
- **Ближайшая цель:** выполнить локально `npm ci`, `npm run build` и `npm run dev`, проверить адаптивность и временные изображения, сохранить зависимость PR № 2 от PR № 1.
- **Не проверено:** локальная сборка и запуск текущей версии, визуальное соответствие макету, домен/хостинг и настройки деплоя.
- **Ограничение:** не менять базу и не сливать PR без подтверждения владельца проекта.
- **Последнее обновление карточки:** 13 октября 2026 года.

## 4. Правила ведения реестра

- Использовать статусы и обязательные поля, описанные в [стандарте документации](DOCUMENTATION-STANDARD.md).
- Не считать задачу завершённой только потому, что она описана в PR или планах.
- Различать подтверждённые проверки, заявления из описаний PR, планы и непроверенные сценарии.
- Не считать локальные изменения частью удалённого репозитория без проверки.
- Не изменять и не сливать проектные ветки без необходимого согласования.
- Обновлять дату карточки после значимых изменений или проверок.
- Перед переносом сверять локальное состояние, ветки, доступы, CI и внешние интеграции по [предпереносному аудиту](REPOSITORY-AUDIT.md).
